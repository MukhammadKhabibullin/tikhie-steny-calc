# Расчёт геометрии, профилей и проёмов

## Реализованные правила

- Ткань: полная площадь стен × 1,05. Окна и двери не вычитаются. Площадь проёмов и чистая площадь стены остаются отдельными справочными метриками.
- Звукоизоляция: сохранено прежнее правило — чистая площадь стены × 1,05. Плинтус: длина стен × 1,05.
- Основной монтаж: сохранены ставки 1 400 ₽ клиенту и 800 ₽ мастерам на м² расчётной ткани с запасом. Дополнительно каждый проём стоит клиенту 6 000 ₽, независимо от типа.
- Зарплата мастеров за проёмы не указана в задании, поэтому не придумана: в интерфейсе показано предупреждение, что она не включена в себестоимость. Маржа требует уточнения этой статьи.
- Числовой ввод: пустое поле даёт расчётное значение 0, ведущие нули удаляются, точка и запятая поддерживаются. Отрицательное вставленное число становится 0; некорректный ввод и значения выше лимита не принимаются. На потере фокуса убираются лишние нули после запятой. Верхний предел размеров — 1 000 000 мм, прочих числовых полей — 1 000 000 000.

## Допущение о соединениях

В прежней модели нет координат, углов и связей стен. Стены одной комнаты теперь считаются упорядоченной цепочкой. Выбранная на чертеже стена влияет только на просмотр и размещение проёма, не на связи стен.

- Старые и новые комнаты по умолчанию открыты. Замкнутость задаёт флажок «Замкнутый контур» при наличии хотя бы трёх стен; четыре стены сами по себе не означают замыкание.
- Для одной отдельной стены базовый профиль считается по её длине, как требует задание.
- Для цепочки из нескольких стен базовый профиль считается по высоте каждого свободного торца; внутренний угол — по высоте каждого соединения, один раз на стык. Горизонтальные направляющие дополнительно не подразумеваются.
- Для замкнутого контура нет свободных торцов, последняя стена соединяется с первой.
- Удаление стены размыкает контур; добавление стены в замкнутый контур сохраняет замыкание. Нулевая длина разрывает соответствующие связи. Геометрическое замыкание по координатам не проверяется: редактора координат в проекте нет.
- Профиль Окно-Откос: сумма `2 × (ширина + высота)` всех проёмов, включая нижнюю сторону дверей, в метрах.
- Для каждого типа профиля применяется 8% запаса. Округление до 0,01 м выполняется по типу профиля в каждой комнате, затем количества суммируются. Режим хлыстов округляет общий метраж каждой позиции вверх до хлыстов по 2 м.

## Автоматические и ручные позиции

`autoSource` однозначно определяет управляемые позиции: базовый, угловой, откосный профиль и монтаж проёмов. Повторный пересчёт сохраняет ID существующей автоматической строки, не размножает её и удаляет ненужную строку. Цены профилей можно редактировать; количество и тип автоматического профиля определяет геометрия. Дополнительные профили добавляются вручную.

Каталог ищется по стабильному ID, затем по точному нормализованному имени. Если позиция отсутствует, используется встроенный прайс-лист с явной отметкой в интерфейсе и без внешнего ключа на отсутствующую запись БД.

Старые профили без признака `autoSource` остаются ручными. При открытии старого проекта сохранённые количества не перезаписываются. Для применения новых правил нужно нажать «Заполнить по геометрии» или изменить геометрию. При переходе со старых ручных профилей на автоматические следует проверить и самостоятельно удалить заменённые ручные строки, иначе они будут дополнительными расходами. Система не пытается угадать, какие старые записи разрешено удалить.

Работы за проёмы сохраняются отдельной строкой; итоговая формула берёт их количество из геометрии и не складывает сохранённую автоматическую строку второй раз. Сохранённые ручные работы учитываются дополнительно. Бланк заказа Excel остаётся материальным бланком: получает актуальные материалы, а не монтажные работы. Печать и текстовое коммерческое предложение включают монтаж проёмов.

## База данных и выпуск

Подготовлен файл `supabase/migrations/20261014_geometry_automation.sql`. Он добавляет:

- `rooms.contour`;
- `walls.sort_order`;
- `project_materials.auto_source`;
- `project_works.auto_source`.

Существующие строки не удаляются и не переклассифицируются. Права доступа не изменяются. Перед выпуском приложения нужно отдельно согласовать и применить миграцию к нужному проекту Supabase. До этого новая версия остановит сохранение на проверке схемы **до** удаления старых данных. Чтение старой схемы поддерживается.

Миграция поставляется отдельно от приложения: перед production-деплоем необходимо подтвердить наличие всех четырёх полей в рабочей БД.

Сохраняется прежнее архитектурное ограничение: многошаговое сохранение через Supabase не является транзакцией. Проверка схемы защищает от её несовместимости, но сетевой обрыв в середине сохранения всё ещё может оставить частичные данные. Полное устранение требует отдельной серверной транзакции и проверки прав доступа — это не реализовано в данной задаче.

## Файлы

- `src/utils/numericInput.ts`, `src/components/NumericInput.tsx` — единый числовой ввод.
- `src/utils/calculator.ts`, `src/utils/geometrySync.ts`, `src/types.ts` — формулы и признаки автоматических позиций.
- `src/App.tsx` — пересчёт, загрузка, сохранение, текстовая смета, исправление сброса пустого проекта.
- `src/components/RoomBuilder.tsx`, `WallDiagram.tsx` — контур, числовые поля, справочные проёмы и подписи.
- `src/components/MaterialsSection.tsx`, `CatalogManagerModal.tsx` — ввод цен/количеств, автоматические строки, корректные цены хлыстов.
- `src/components/SummarySection.tsx`, `ProjectHeader.tsx`, `DashboardScreen.tsx` — согласованные суммы и тексты.
- `src/services/supabaseClient.ts`, миграция — сохранение метаданных, порядка стен, привязок проёмов; ошибки чтения больше не выдаются за пустой проект.
- `package.json`, `tests/` — тесты и локальная страница проверки компонентов без доступа к рабочей БД.

## Проверка

`npm test` проверяет ввод, ткань, топологию 0–4 стен, проёмы, несколько комнат, повторный пересчёт, ручные позиции, единицы, цены, монтаж, чтение/сохранение через изолированный адаптер Supabase и отказ до записи при отсутствии миграции.

`npm run lint`, `npm run build`, `git diff --check` проверяют код и сборку.

Для проверки интерфейса: `npm run dev`, открыть `/tests/ui/index.html`. Эта тестовая страница не включается в production-сборку и не сохраняет данные. Реальное сохранение/повторное открытие проекта в Supabase необходимо проверить после применения миграции в согласованном окружении.
